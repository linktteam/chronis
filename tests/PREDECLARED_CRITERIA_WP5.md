## 2. Data
Model structure for every arm and user: K=2, F=4, L=2, `max_duration` 25 (as N18). **Model misspecification of K, F, L is not studied** (the generator's truth is used).
* **Population generator** (`data/synthetic_population.py`). The centre is the existing generator's parameters: `A = 0.75 I`, `b = 0`, `Q = 0.3 I`, loadings 1.5 on `f mod L`, `d_k = (k - 0.5) * 4`, `R = 0.05`, segment durations lognormal(ln 15, 0.3) clipped to 8..30, regimes alternate. A user is the centre times a user-specific perturbation drawn from its own generator `default_rng([seed, 1])` (separate from the data stream, so with all spreads 0 the data equal `continued_synthetic(seed)` exactly; this is a test): intercepts `d_kf += 0.6 * e`; loading of feature f `*= exp(0.15 * e)`; `A = a I` with `a = 0.75 + 0.05 * e` clipped to [0.4, 0.9]; `Q = 0.3 exp(0.25 e) I`; `R = 0.05 exp(0.25 e)` (scalar per user); mean dwell `15 exp(0.2 e)`; all `e ~ N(0,1)`.
  **Reason for the sizes:** there are no real population data here (UNKNOWN how heterogeneous real users are), so these are assumptions chosen to make users clearly different but of one structure: the intercept spread 0.6 is 15% of the regime separation (4.0) and about half the within-regime noise SD (about 1.3); loadings, variances and dwell vary by 15 to 25%. **The conclusions hold only for populations at least this homogeneous**; the atypical control probes 3 times this spread.
* **Atypical-user generator** (seeds 9001..9012): the same perturbations with every `e` multiplied by 3 (three times the population spread, so each user is about 3 SD from the centre in every coordinate). Generator self-check: the norm of the draw vector of every atypical user exceeds the largest norm among the 24 evaluation users (test).
* **Training lengths** (segments of the generator, mean about 15 steps each): **2, 4, 8** training segments = about **30, 60, 120** steps; held-out part **2 segments** (as N18). The realised T is reported.
* **Population users for the prior** (8001..8020): **12 training segments** (about 180 steps), no held-out part. Reason: the shared model is meant to come from users who have already been in the system a while; at about 120 steps the engine fits well (WP3 V2).

## 3. Arms (scored on the held-out part: mean one-step-ahead predictive log density per step, forward filter from t=0 over train + held-out, parameters frozen; per-seed difference to `gauss`; paired standard error with ddof 1, margin 3.0 se; identical to N18)
* `gauss`: a single Gaussian on the training data (N18's `baseline_scores`).
* `personal`: `DualTimescaleHSSM(seed=data seed).fit(X_train, n_iter=20)`, one fit, random initialisation (N18's convention; N18 used 25 iterations for one seed only, here 20 for all).
* `shared`: no fitting; the prior's parameters in an engine object.
* `shrinkage`: `ShrinkageDualHSSM(shared_prior=prior, n0=n0).fit(X_train, n_iter=20)`: **initialised at the shared parameters** and M-step regularised toward them (section 5).
* `warm` (ablation, not a criterion arm): the same with `n0 = 1e-6`, i.e. initialised at the shared parameters and not regularised. It separates the effect of the prior in the M-step from the effect of the warm start.

## 4. The shared prior (`backbone/hssm/shrinkage.py::build_shared_prior`)
1. **Reference fit:** population user 8001 fitted with 5 random restarts (constructor seeds 8001..8005, 30 iterations); the healthy fit with the highest log-likelihood is the reference. (Healthy = `fit_degraded_` false and not `NUMERICAL_FAILURE`.)
2. **Round 1:** every population user is refitted by the plain engine EM (30 iterations) **initialised at the reference parameters** (this keeps labels and latent coordinates close to the reference).
3. **Alignment (before pooling), per user and per round:**
   (a) **regimes**: Hungarian matching on the frame-free per-regime observation mean `o_k = d_k + C_k (I - A_k)^-1 b_k` against the reference; the match is *ambiguous* if the best total squared distance is not at most half the second-best (K=2: the swapped assignment); ambiguous users are excluded and counted.
   (b) **latent frame**: the linear map `M` (L x L) minimising `sum_k ||C_k^u M - C_k^ref||_F^2`; the user's parameters are transformed by `m' = M^-1 m` (`A' = M^-1 A M`, `b' = M^-1 b`, `Q' = M^-1 Q M^-T`, `C' = C M`). A user fails if `cond(M) > 10` or `||C^u M - C^ref||_F / ||C^ref||_F > 0.5`; failed users are excluded and counted. (Reasons: a frame map with a condition number above 10 or half the loading magnitude unexplained is not a relabelling of the same model.)
4. **Pooling:** the mean of each aligned parameter over the users that passed. **Minimum number of users: 10** (the pooled mean of a parameter with between-user spread s has standard error s / sqrt(n); below 10 users the centre is too noisy to call "population"); fewer raises `PriorBuildError`.
5. **Round 2:** repeat 2 to 4 with the round-1 pooled parameters as the initialisation and as the alignment reference. The prior is the round-2 pooled parameters. The change of the pooled parameters between rounds is reported (reference dependence).
6. **The prior holds aggregate parameters only:** `pi, A_slow, dur_mu, dur_sigma, A_fast, b_fast, Q_fast, C_obs, d_obs, R_obs, m0, P0` (all per regime), `K, F, L`, `n_users` and counts (excluded users). No data, no sequence, no per-user parameter. Test: the object's attributes, the shapes and the serialised JSON are checked against a whitelist; a prior that stores a data array fails the test.

## 5. Shrinkage (which parameters, how, why)
`n0` = pseudo-steps **per regime** (so the weight of the prior on regime k's parameters is about `n0 / (n0 + W_k)`, `W_k` = expected number of the user's steps in regime k). Conjugate MAP in closed form, expressed as pseudo-data of the SHARED model:
* **Shrunk:** `A_fast, b_fast, Q_fast` (add `n0` x the expected sufficient statistics of the shared dynamics, using the stationary moments of regime k, to `G, H, S, W` through the existing `_dynamics_sufficient_stats` hook); `C_obs, d_obs, R_obs` (same, per feature); `A_slow` and `pi` (pseudo-counts `n0 / Dbar_k` transitions, `Dbar_k` = mean of the shared duration pmf of regime k; one pseudo-segment is about 15 steps); `dur_mu, dur_sigma` (pseudo-segments `n0 / Dbar_k` distributed as the shared duration pmf are added to the weighted counts of the existing Nelder-Mead fit).
* **Not shrunk:** `m0, P0` (the engine never updates them: they stay at their initial values, which are copied from the prior), and the latent coordinate frame (it is fixed by the warm start, not estimated).
* **Reason for MAP in the shared frame, with a warm start:** the engine's latent coordinates and labels are arbitrary per random initialisation, so a prior in the shared frame only makes sense if the user's fit starts in that frame.
* **Prior uncertainty and `m_t_std`:** the prior's uncertainty does NOT enter `m_t_std`; `estimate_states` is the unchanged engine method run with the final (shrunk) parameters. Recorded as a property of the prototype (`prior_uncertainty_in_m_t_std = False`). N17 is not addressed.
* **EM guard:** the engine's monotonicity guard compares the unpenalised log-likelihood, which a MAP step may lower; a fit can therefore stop early (`REJECTED_UPDATE`) at the previous parameters. The guard is not changed (default path untouched); the number of such fits is reported per arm.
* `ShrinkageDualHSSM` without a prior, or with `n0 = 0` and no warm start, is bit-identical to `DualTimescaleHSSM` (test).

## 6. Choosing n0 (development seeds 6001..6012 only)
Grid **5, 20, 80, 320** pseudo-steps. For each n0 and each length: `lower(n0, length)` = mean - 3 se of (`shrinkage` - `gauss`) over the 12 development seeds. **Rule: choose the n0 that maximises `min over the three lengths of lower(n0, length)`; ties go to the smaller n0.** All grid values, all arms and the `warm` ablation are reported. The chosen value is written to `integration_report/wp5/N0_FROZEN.md`, committed, and only then are seeds 7001..7024 and 9001..9012 touched. The development seeds also serve for debugging the prototype; nothing else touches the evaluation seeds before the freeze. A bug found after the freeze is a dated amendment plus a re-run, reported.

## 7. Criteria (evaluation: seeds 7001..7024, 3 lengths; atypical: 9001..9012). "mean", "se" are those of the per-seed paired differences; `lower = mean - 3 se`.
1. **Cold-start claim:** at EACH length (30, 60, 120), `shrinkage` - `gauss`: lower > 0. (3 se as in N18, for comparability; with 24 seeds one-sided p about 0.003.)
2. **No regression:** at each length, `shrinkage` - `personal` and `shrinkage` - `shared`: mean + 1 se >= 0 (the owner's tolerance).
3. **Atypical control:** at 120 steps, `shrinkage` - `personal` on seeds 9001..9012: mean + 3 se >= 0. At 30 steps and 60 steps reported only.
4. **Off by default:** the engine without a prior is bit-identical to `16c3431`: `ab_identity_wp4.py` against `git archive 16c3431`, expected 2290 values, 0 differences (count reported); `ShrinkageDualHSSM` without prior equals `DualTimescaleHSSM` (test).
5. **Privacy structure:** the whitelist test of section 4.6 passes (and fails on a prior that stores data).
6. **The study discriminates.** Each variant below replaces `shrinkage` in criteria 1 to 3 (evaluated on the same seeds) and MUST make at least one of them fail: (i) `n0 = 1e-6` with the warm start kept (`warm`); (ii) prior ignored altogether = the `personal` arm; (iii) `n0 = 1e6` (prior dominates); (iv) the prior built with a random label permutation per user before pooling (alignment broken); (v) the prior built from a shifted population (all intercepts `d` shifted by +2.0, which is half the regime separation). **If (i) passes all three criteria, criterion 6 is reported as FAILED for it** ("the criteria cannot tell regularisation from warm start") and, by the brief's rule, nothing is integrated; the owner decides.
If criterion 1 is impossible at 30 steps for a nameable reason (for example the prior itself is poor: `shared` below `gauss`), that is reported and the criterion stays as written.
Criteria 1, 2 and 3 apply to the frozen `n0` only. Whatever happens, every arm's score at every length is reported, not only the winners.
