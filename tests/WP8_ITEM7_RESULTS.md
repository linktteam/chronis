# WP8 Item 7: expert-review tagging (results)

Labels: RUN = executed in this container and the output is in `wp8_evidence/`; READ = read in code or docs; UNKNOWN = not established.
No evaluation seed was touched; this item has no fit-based study.

## What was built (READ)
- Tag `EXPERT_REVIEW(identity-distance)` at every definition and use of the matching distance, the ladder weights and the alignment thresholds in `backbone/hssm/`: **32 sites** in `lineage.py`, `ordering.py` and `refit_policy.py` (module docstrings, config classes, the distance vectors, the Hungarian alignment and its margins, the acceptance rule, the combined two-channel cost, the identifiability gate, the ladder weights, the rung roles, the reliability test, the record that carries the status).
- `docs/EXPERT_REVIEW_REGISTER.md` is **generated** by `integration_report/wp8/scripts/expert_review_register.py --write` (AST and tokenizer scan, no line numbers so unrelated edits do not make it stale). It also prints every number under review, read from the code (ladder config, rung roles, alignment config, channel config, the 0.5 ratio ceiling, the refit cadence, the status). `--check` exits 1 when the committed register differs from the code.
- `lineage.EXPERT_REVIEW_STATUS = "PENDING"`, carried by every `LineageRecord` (default of the field), by `as_dict`, and by the additive `HSSMResult.lineage`; it stays PENDING until the owner records a sign-off in the register and in that constant. The register's sign-off section says nobody has signed off.
- Contract line (`docs/INTEGRATION_CONTRACT_HSSM.md` 9.10): names the register, the tag, the status, and that the test fails when the register is stale.

## Tests and mutants (RUN)
- `tests/test_wp8_item7_expert_review.py`: **50 tests.** The committed register equals what the code generates; the register lists every tagged site exactly once and no site that does not exist; a removed, added or edited tag changes the generated register (negative controls on synthetic modules); a docstring that only mentions the tag is not a site; a dangling tag comment is refused; a comment belongs to the definition below it; methods are named by class; 21 required sites stay tagged (one test each); every threshold field of the configuration classes is a watched name (added after the Item 4 freeze introduced `dual_engine`); **a scan of every function in `backbone/hssm/` fails when it mentions a watched name (the matching functions, the distance and the thresholds) without the tag**, with synthetic positive and negative controls for name and attribute uses; the watched names must still exist (a rename cannot silence the scan); every kind of record (NEW_LINEAGE, ALIGNED, K_CHANGED, CONTINUITY_UNVERIFIED) and the result field say PENDING; `--check` fails on a missing or stale register and passes on a current one; the register prints the numbers under review; the contract names the register.
- Mutants: **25 of 25 killed** (`wp8_evidence/item7_mutation_results.txt`, `integration_report/wp8/scripts/mutation_item7.py`).
- Finding while building: the use scan found five functions that used the identifiability gate or the ladder thresholds without a tag (config validation, the record writer, the proposal helper, `as_dict`); they were tagged. The register was regenerated after the Item 4 freeze (RUN: `--check` reported it stale before `--write`, which is the stale-register test doing its job); it now shows `min_separation = 4.0`, the three classes of pair (`dual_engine` and `cross_engine` with `calibrated=False`) and the frozen baseline threshold. The Item 7 mutants were re-run on the frozen code.

## Limits (UNKNOWN or by design)
- The scan is by name. A function that reaches the distance only through a name outside `WATCHED` is not caught; `WATCHED` is a list a reviewer should read. The register lists what the code marks, not what an expert has judged.
- No expert has reviewed anything; PENDING is the truthful status.
